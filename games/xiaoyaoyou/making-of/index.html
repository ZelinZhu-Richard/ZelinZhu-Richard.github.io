逍遥游 How it was built

This is a short browser game about the opening of the Zhuangzi. You are Kun, a small fish in a dark northern sea, and you grow until the stone forest below looks small. Drag the line above. The left side is the painting it started from. The right side is one frame of the game, rendered live.

The painting is AI concept art. It set the target and it stays out of the game: nothing you see while playing is drawn from it. The rest of this page is how the right side got made, and where it still falls short of the left.

Start from drawings, not from a mesh

The painting says how the sea should feel. It can't say how Kun is built, so a reference sheet does that job: side, top and front views on flat grey, plus the two textures that cover the body and fins.

Kun is written, not sculpted

Every mesh in the game comes from Python running inside Blender: cross-sections lofted along a curved spine, fins as thin sheets traced from the sheet, UVs laid out in code. There are no downloaded or AI-generated models.

Each build is scored against the sheet. A script renders the model through a matched orthographic camera and overlays it on the reference, so a mismatch shows as a number and as colored pixels instead of as an opinion.

One frame, one layer at a time

Geometry alone looks like a toy. Nearly all of the mood comes from light moving through water, and it is computed live, every frame, in the browser.

Composition is camera work

For a long time the game looked wrong in a way no shader could fix. Fog, shafts and materials were all improving, and the frame still felt nothing like the painting. The reason was composition. The camera sat too far back and too level, so Kun was small and the world was empty.

Moving the camera low and close, looking up, did more in an hour than the previous rounds of lighting work. Dark cliffs at the edges of the frame, a stone forest in three layers, and a warm key light finished the job. These are the same frames before and after that change.

Who did what

I wrote the brief, chose the look and approved each milestone. Claude Code builds and Codex reviews. Codex built the earliest milestones, including Kun's first model, before the roles split this way. As reviewer it sees only fresh screenshots, measurements and the concept art. It never sees the source or the builder's notes, so it can only judge what the game actually renders.

  1. Images Concept art and reference sheets set the target.
  2. Python in Blender Code builds each mesh, scored against the sheet.
  3. three.js Static modules, with custom shaders for light, water and mist.
  4. Capture A headless browser on a real GPU records screenshots and metrics from a clean commit.
  5. Independent review Codex returns pass, fix or block. A fix goes back to the top.

Separating the builder from the reviewer mattered more than expected. The reviewer caught a camera change that clipped Kun's tail on phones, and refused pillars that looked manufactured. It also could not see intent, so it kept flagging small artifacts while the bigger problem was composition. That diagnosis came from a human looking at the frames.

Where it still falls short

Side by side with the painting, the differences are easy to find. Kun's tail is a small fluke where the painting has a sweeping veil. The fins have the crisp edge of cut paper instead of dissolving into the water. The painted forest has far more small detail than a real-time scene can hold. And on a phone the journey is still untested on real hardware.

The title screen uses a real frame from the game for the same reason this page exists: the painting promises more than the game shows, and a visitor should see what they'll get.
